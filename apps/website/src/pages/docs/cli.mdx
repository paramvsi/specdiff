<Callout type="info">The npm package is `specdiff-cli`; once installed, the command is `specdiff`. With npx, use `npx specdiff-cli`.</Callout>

## Compare locally

```bash
npx specdiff-cli old.yaml new.yaml
```

Opens the app on `127.0.0.1` with both files loaded. Nothing is uploaded. Add `--no-open` to print the URL instead of opening a browser, and `--port <port>` to pick the port.

Given one file, the CLI compares `HEAD:<file>` with the working copy and prints the summary; see [Pre-commit hook](/docs/pre-commit/).

## Read from git

Any argument can be a git revision and path, `rev:path`:

```bash
npx specdiff-cli main:openapi.yaml openapi.yaml
npx specdiff-cli v1.5.0:api/openapi.yaml HEAD:api/openapi.yaml
```

Split specs resolve their relative `$ref`s from the same revision. Revisions that start with `-` are refused.

## Gate a build: `--ci`

```bash
npx specdiff-cli main:openapi.yaml openapi.yaml --ci
```

```text
Comparing main → working tree…
✖ 4 breaking  ? 1 possibly  + 14 safe  ¶ 9 docs only
Suggested version: 2.0.0 (major)
  ! POST /v1/payments › requestBody › currency  request-property-became-required
  ! GET /v1/payments › query limit › maximum  request-param-constraint-tightened
  ! DELETE /v1/refunds/{id}  endpoint-removed
  ! components.schemas.Card › last4  response-property-removed
Exit code 1 · breaking changes found
```

The report goes to standard output (or `--out`); the summary above goes to standard error.

| Flag | Values | Default |
|---|---|---|
| `--ci` | | Print the report and exit; don’t open the app |
| `--fail-on` | `breaking`, `possibly`, `missing-version-bump`, `none` | `failOn` from `.specdiff.yaml`, else `breaking` |
| `--format` | `md`, `json`, `html` | `md` |
| `--config` | path to a `.specdiff.yaml` | `./.specdiff.yaml`, then the repo root |
| `--allow-external-refs` | | Off. In `--ci` mode remote `$ref` URLs are not fetched without it. In the local UI remote `$ref`s are fetched, and relative ones inside them on the same host; this flag also follows refs to other hosts. At most 50 files and 25 MB |
| `--out` | file to write the report to | standard output |

Exit code 0 means nothing failed the gate, 1 means it did, and 2 means a usage or input error (a missing file, a file that does not parse, an invalid `.specdiff.yaml`). Accepted [review decisions](/docs/review/) don’t fail it; rejected ones always do.

## Use in any CI

The CLI needs Node and git, nothing else. Fetch the base branch so `rev:path` can read it.

### GitLab CI

```yaml title=".gitlab-ci.yml"
api-changes:
  image: node:26
  script:
    - git fetch origin main --depth=50
    - npx specdiff-cli origin/main:openapi.yaml openapi.yaml --ci --format md > specdiff.md
  artifacts:
    when: always
    paths: [specdiff.md]
```

### Jenkins

```groovy title="Jenkinsfile"
pipeline {
  agent { docker { image 'node:26' } }
  stages {
    stage('API changes') {
      steps {
        sh 'git fetch origin main'
        sh 'npx specdiff-cli origin/main:openapi.yaml openapi.yaml --ci --fail-on breaking'
      }
    }
  }
}
```

### Plain shell

```bash
#!/bin/sh
set -e
git fetch origin main
npx specdiff-cli origin/main:openapi.yaml openapi.yaml --ci --format json > report.json
```

The JSON report follows a published JSON Schema, so other tools can read it. Print the schema with:

```bash
npx specdiff-cli schema > specdiff-report.schema.json
```

Inputs that are not OpenAPI (JSON, YAML, text) are compared too, but only OpenAPI changes can fail the check.

## Changelogs and feeds: `changelog`

```bash
npx specdiff-cli changelog v1.yaml v2.yaml                 # release notes (Markdown)
npx specdiff-cli changelog main:openapi.yaml openapi.yaml --format keep-a-changelog --date 2026-11-15
npx specdiff-cli changelog v1.yaml v2.yaml --format atom \
  --feed-url https://api.example.org/changelog.xml --title "Payments API" --out public/changelog.xml
```

Writes the changelog of two OpenAPI specs. With `--format atom` it writes an Atom feed to host next to your docs, so readers can subscribe to API releases. For each new release, pass the feed you already publish with `--append`: the new release becomes the first entry, older entries stay below it, and running the same release again replaces its entry instead of adding a second one.

```bash
npx specdiff-cli changelog v2.yaml v3.yaml --format atom --feed-url https://api.example.org/changelog.xml \
  --title "Payments API" --append public/changelog.xml --out public/changelog.xml
```

| Flag | Default |
|---|---|
| `--format md\|atom\|keep-a-changelog\|slack\|pr-comment` | `md`: release notes |
| `--feed-url <url>` | Required with `atom`: where the feed is published (its id and `rel="self"` link) |
| `--site-url <url>` | With `atom`: the site the feed links to |
| `--title <title>` | `API changelog` (feed title), or the heading for `md` and `slack` |
| `--release <version>` | The suggested version |
| `--date <date>` | Now (Atom `updated`); the Keep a Changelog heading date |
| `--append <feed.xml>` | With `atom`: add this release to an existing feed |
| `--out <file>` | stdout |

In the app, **Export → Changelog feed (.xml)** asks for the feed URL and title and remembers them in this browser.

## Viewer timeline: `history`

```bash
npx specdiff-cli history openapi.yaml --out versions.json
```

Walks git tags (or, when no tag has the file, the last commits that touched it) and writes a version set for the [Viewer](/docs/react/) timeline.

| Flag | Default |
|---|---|
| `--out <file>` | `versions.json` |
| `--max <n>` | `20`: the most versions to keep |

## Git diff driver

Make `git diff` and `git log -p --ext-diff` show the semantic changelog for spec files:

```bash
git config diff.specdiff.command "npx specdiff-cli git-diff-driver"
echo "openapi.yaml diff=specdiff" >> .gitattributes
git log -p --ext-diff openapi.yaml
```

`git log` and `git show` only run external diff drivers with `--ext-diff`.
