Rules / Request bodies
!Breakingrequest-property-became-required

An optional request property became required

A property that clients could leave out of the request body is now in the schema’s required list.

before.yaml

paths:
/v1/payments:
post:
requestBody:
content:
application/json:
schema:
required: [amount]
properties:
currency: { type: string }

after.yaml

paths:
/v1/payments:
post:
requestBody:
content:
application/json:
schema:
required: [amount, currency]
properties:
currency: { type: string }

Who it breaks

Every client that sends this request without the property. They get a validation error, usually 400 Bad Request, on the first call after you deploy. Clients generated from the old spec don’t know the field exists.

How to avoid it

  1. Keep the property optional and give it a default the server applies.
  2. Or release the change in a new major version, and say so in the changelog.
  3. Or accept the property for a while without requiring it, then require it after a deprecation period.

Example message

Changelog line
**Breaking:** `POST /v1/payments` now requires `currency`
in the request body.
