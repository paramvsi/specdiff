Docs / Modes

Compare two OpenAPI specs

Find every change between two versions of an API, see which ones break clients, and get a changelog. Takes about two minutes.

Open both versions

Open the app and add the older spec on the left and the newer one on the right. You can paste, drop a file, drop a folder or ZIP for split specs, or load a URL. GitHub file links are converted to raw links for you.

Comparing branches? From a terminal, npx specdiff main:openapi.yaml openapi.yaml reads both versions straight from git.

Read the summary

The summary counts changes by severity and suggests the next version number. If info.version doesn’t match what changed, Specdiff says so.

!BreakingExisting clients will fail.
?Possibly breakingSome clients may fail.
+SafeAdditions and relaxed rules.
¶Docs onlyDescriptions and examples.

Review each breaking change

Open the workspace to step through changes. Each one shows the before and after, who it breaks, and how to avoid it. Accept or reject it, and your decision is saved for the CLI and pre-commit hook.

.specdiff/decisions.json
# .specdiff/decisions.json
{
  "7c1e…a94f": { "decision": "accepted",
                 "note": "Card.last4 removed in 2.0.0" }
}

Export the changelog

Pick a template, edit the text, and copy or download it. Release notes, Keep a Changelog, a PR comment and a Slack message are built in.

Specdiff reads specs; your editor writes them. Nothing in Specdiff changes your files.
