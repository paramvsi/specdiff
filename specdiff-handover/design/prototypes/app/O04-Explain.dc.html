POST/v1/payments!Breaking

Request field currency is now required

What changed

currency moved into the request body’s required list. Before, a payment without it defaulted to the account currency.

Who it breaks

  • Web and mobile apps that call POST /v1/payments without currency
  • Partner integrations built on SDK 1.x, where currency is optional
  • Retry jobs that replay stored v1 request bodies

What they’ll see

400 Bad Request with missing required property: currency, on the first call after you deploy.

How to avoid it

Pick one, then re-run the comparison:

# Option 1 · keep it optional, with a default
currency:
  type: string
  default: USD
required: [amount]
# Option 2 · ship it in 2.0.0 and say so
info:
  version: 2.0.0
