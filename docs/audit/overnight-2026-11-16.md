## Morning decisions
- **M-1 (row 12):** with `--allow-external-refs`, should the CLI also follow *relative* `$ref`s found inside a fetched remote file (resolved against that file's URL)? Today they stay unresolved. Default kept: no (smaller network reach).
- **M-2 (row 3):** integers beyond 2^53 lose precision in JSON/YAML mode. Options: (a) leave, (b) flag "number too large to compare exactly" as a warning, (c) compare such numbers by their source text. Suggest (b).
- **M-3 (row 14):** History on a phone shows the desktop table, scrolling sideways with the Result column cut off. There is no phone design for A-11. Options: (a) leave, (b) stack each row as a card below 640 px (Mode chip, files, result on separate lines). Suggest (b); it is a layout change, so not done.
- **M-4 (row 17):** Unicode normalisation. Should Text mode get an "Ignore Unicode normalisation (NFC)" option, or a note on lines whose sides are equal after NFC? Adding an option touches the options UI. Suggest: a one-line note on such rows, no new option.
- **M-5 (row 28):** normalise share passphrases to NFC before key derivation? Fixes accented passphrases typed differently on two systems, but a locked link already made with a non-NFC passphrase would stop opening. Safe variant: try the passphrase as typed, then its NFC form. Suggest the safe variant.
- **M-6 (row 31):** `$ref` siblings are merged into the target in `deref` (`openapi/load.ts:261-271`) and keep the target's location, so a sibling change is reported against the shared component. Severity is right; the location and the "changed once for all users" grouping are wrong. Proposed fix: `Resolved` carries `siblings` and the referencing location; `compareResolved` (`rules/schema.ts:597`) compares the bare target via `viaRef` as today, then compares `{...target-type-context, ...siblings}` at the use site. Touches every schema rule's location, so not done unsupervised. Severity of impact: medium (misleading path, no missed breaking change).
- **M-7 (row 35):** add a rule `parameter-serialization-changed`: a parameter's effective `style`/`explode` (defaults resolved per `in`; Swagger 2.0 `collectionFormat` arrives as these after the upgrade) differs. Suggested default severity **breaking** for request parameters (old clients send the old shape). Needs fixtures under `fixtures/rules/parameter-serialization-changed/` and a rules-reference page (generated). CLAUDE.md rule 10 asks before setting a rule's severity, so not added.
- **M-8 (row 48):** JSON Schema `dependentRequired` (3.1): adding `{a: [b]}` to a request schema makes `b` required whenever `a` is sent, which breaks some existing requests, and nothing reports it. Options: (a) extend `request-property-became-required` to cover it (same severity, new message "required when `a` is sent"), (b) a new rule, (c) leave it (rare in OpenAPI). Suggest (a) with a fixture.
- **M-9 (row 56):** two security changes have no rule. (a) `security-removed-from-operation`: an operation that required auth now requires none. Not breaking for clients, but a reviewer must see it; suggest severity **safe** with an explanation that calls out the dropped auth, so it shows in the review list. (b) `security-scope-removed-from-scheme`: a scope deleted from a scheme's flow; clients that still request it are refused by the auth server; suggest **possibly**. Both need fixtures and a docs/06 row.
