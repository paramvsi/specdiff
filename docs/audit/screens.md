# Screen audit: build vs approved design (78 frames)

Independent audit, 2026-11-15. No product code, tests or config were changed.

**Method.** `pnpm build` (turbo, all 9 tasks cached), then served: app with `vite preview` (http://localhost:4173/app/), the dev-only `/_ds` sheet with the app dev server, the Viewer harness (`vite packages/viewer/harness`, port 5174) and the website with `astro preview` (port 4321). Each frame was driven into its state with Playwright (Chromium, `reducedMotion: 'reduce'`, `colorScheme` light/dark as the frame shows, 1440 px wide or 390 px for `*-390` / `M0*`), screenshotted to `/tmp/sd-screens/<frame>.png`, and compared **by eye** with `specdiff-handover/design/screens/**.jpg` section by section (B-3: JPGs are not pixel-matchable). Scripts: `/tmp/sd-screens/app/*.mjs`, `/tmp/sd-screens/viewer/*.mjs`, `/tmp/sd-screens/website/shoot.mjs`.

**Rulings applied** (a difference they cover is not a defect): B-2 (4 breaking / 1 possibly / 14 / 9; real rule counts), B-11 (`npx specdiff-cli`), B-15 (no statement-level renames in code mode), B-16 (native `<select>` version picker), B-19 (undesigned settings panes), B-20 (raw-diff markers mouse-only), B-23 (moved rows use `↕`), B-24 (patch view inside Compare), D-13 (date placeholders), decision 5 (Home v1 superseded → N/A).

**Verdicts.** Matches 0 · Minor differences 39 · Major differences 36 · Missing 0 · N/A 3 (app 0/13/26/0/0, Viewer+phone 0/17/7/0/0, website 0/9/3/0/3).

No frame is wholly missing, but several **designed states inside frames cannot be reached** in the product; each is called out in its row ("Partly"): A-02 in-progress parsing, A-07 tree states via the sample, A-09 rename/move/format, O-13 action toasts, A-05 consumer filter via HAR, V-05 picker popover (native select, B-16), V-06 (harness only, Spring Boot not run).

**Cross-cutting app differences** (counted once here, repeated in rows only where they matter):
- Top bar: logo inset 64 px vs 40 px; an extra "More" (hamburger) button and, on OpenAPI results, a "Copy for LLM" button that no app frame has; utility screens (History, Settings, Saved sources, Parsing, Patch) keep the full comparison top bar instead of the frame's own actions.
- Change titles everywhere are generic rule sentences ("Request property `currency` became required") instead of the designed human titles ("Request field currency is now required"), and explanation strings show **literal Markdown backticks**.
- Dark mode: selected chips / segments / switch tracks / count badges lose contrast (some text becomes invisible).
- Dialogs lack the header divider and grey footer band used by every designed dialog.
