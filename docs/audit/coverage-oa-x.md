**End to end** here means one of three things: a Playwright test that drives the built app, a test that runs the built CLI, or a test that imports a built package. Unit tests (`**/*.test.ts`) count only as supporting evidence. New tests are in `e2e/coverage-oa-x.spec.ts`. Each test title starts with its feature ID.

## DEFECTS (kept as `test.fail()`)

1. **X-06: the Workspace change tree shows severity by colour alone.** Each tree row uses `SeverityBadge compact` (`packages/ui/src/components/SeverityBadge/SeverityBadge.tsx:15-21`, `apps/app/src/screens/openapi/Workspace.tsx:94`). That is an 8 px coloured dot (`SeverityBadge.module.css .dot`) whose label exists only as visually-hidden text. docs/02 X-06 and CLAUDE.md rule 4 require a symbol, and docs/09 l.25 says tight lists use "the compact chip (11 px, 13 px symbol)". Observed with `test.fail` removed: none of the 20 tree rows has a visible `! ? + ¶`. Rows read like "POSTRequest field is now requiredcurrency", where "Breaking" is clipped to 1 px. The same component is used for the compact dots in the Raw diff side list and in "Changes that affect you" [inferred: same `compact` prop, not separately asserted].

## Skipped and not end to end

- 6 `OA-05 rule fixture` cases are skipped: `sunset-date-moved-earlier`, `sunset-date-removed`, `sunset-inside-grace-period` (`.1` and `.2`), `endpoint-removed-after-deprecation.2` and `request-param-removed.2`. Their `expected.json` pins `today: 2026-11-15`, and the CLI has no option to set "today", so a CLI run would depend on the wall clock. The OA-17 tests cover the same rules with dates relative to now. The two non-sunset `.2` pairs are covered only by the unit test `packages/core/src/rules/fixtures.test.ts`.
- 1 phone-only test is skipped in the desktop project (`@phone X-07`), and it passes in the phone project.
- X-03 note: after the first load, the PWA service worker precaches every chunk, including tree-sitter, Viewer and lang chunks. The test counts only page-initiated fetches. Whether background precaching is acceptable under "loaded on demand" is a ruling for the owner, not a test result.
- OA-11 note: the callout follows a fresh `#change=` load. Changing only the hash within the same document was not tested, and the test reloads first.
- X-05 "WCAG AA" as a whole and X-02 "60 fps scrolling" cannot be proven by automation here. Axe and target-size checks are proxies, and no frame-rate measurement is made.
- OA-21 "respected by the pre-commit hook": precommit.spec drives the hook script on a staged breaking change. It does not combine the hook with an app-made decisions.json. The CLI half of that loop is covered.
